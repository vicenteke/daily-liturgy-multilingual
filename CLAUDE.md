# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`daily_liturgy`: a Python library returning the Catholic Mass readings of a day, plus season, week, color and celebrations, as a Pydantic model, per locale. `README.md` is the user-facing doc (supported locales table, interface, example). Keep it in sync when adding a locale or changing the model. The public API is a single function: `get_daily_liturgy(date=None, locale="en-us") -> DailyLiturgy`.

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest                                   # offline tests (network tests deselected by default)
.venv/bin/pytest -m network                        # hit the live sources
.venv/bin/pytest tests/test_en_us.py::test_sunday_has_second_reading   # single test
```

## Project rules

- **One public function per file, named after it.** For example, `get_daily_liturgy_en_us.py` exports only `get_daily_liturgy_en_us`. It goes first, right after imports and module constants, and every other function in the file is private (`_` prefix). Keep files under ~80 lines (a soft limit) by splitting into more such files.
- **Functions only.** No classes for logic. The only classes allowed are Pydantic models (`models.py`) and exception types (`exceptions.py`).
- **Prefer official Catholic sources** (bishops' conferences, the Holy See). Never bypass access controls (bot challenges, domain-gated APIs). A non-official source needs the user's explicit approval. So far that's pt-br's Canção Nova, which republishes the CNBB text, de-de's Schott (Erzabtei Beuron), and iBreviary for la (no official site publishes the daily readings in Latin) and for en, es-es, pt-pt, ro-ro, gl-es and ar. When an official source exists for a locale, it owns the key (e.g. it-it is built from CEI and French from AELF, so iBreviary's Italian function exists but isn't registered, and its French one was removed).
- **Scope is Mass readings**, not the Liturgy of the Hours.
- Locales are plain lowercase strings like `"en-us"` (or just the language, `"la"`, `"en"`, `"ar"`, when the text isn't tied to one country). An unknown locale must raise `UnsupportedLocaleError`.

## Architecture

- `daily_liturgy/get_daily_liturgy.py`: normalizes the locale and dispatches through the `SUPPORTED_LOCALES` dict (locale string → `fn(date) -> DailyLiturgy`). It then sets the result's `locale` to the normalized key, so one function can serve several keys.
- `daily_liturgy/locales/<locale_folder>/`: one package per locale. The folder uses underscores (`en_us`, `es_mx`, `pt_br`), because hyphens aren't importable. Its `__init__.py` re-exports only `get_daily_liturgy_<locale_folder>` (e.g. `get_daily_liturgy_en_us`), defined in the file of the same name. That function just composes the locale's other single-function files (fetch → select → parse) into a `DailyLiturgy`.
- `models.py` is shared by all locales and kept deliberately flat: `DailyLiturgy(date, locale, source_url, season, week, color, celebrations, readings)`. `Color`, `Season` and `Rank` are `str` enums. `color` is `None` when it can't be determined. `Celebration(name, rank)` has `rank=None` when the source names the day without a rank. Each `Reading(type, citation, content, alternatives)`. `type` is the heading as published by the source ("Reading 1", "Responsorial Psalm", "Alleluia", "Gospel"…). `alternatives` is a `list[Reading]` of texts that may be read instead of that one (USCCB's "or", Canção Nova's "ou"). Each alternative has the same `type` as the reading it replaces. On days with several Masses, only one is returned (see the locale's notes).

- `daily_liturgy/ibreviary/` (a sibling of `calendar/`) holds the shared iBreviary code, plus one folder per language (`latin/`, `english/`, `spanish/`, `portuguese/`, `romanian/`, `galician/`, `arabic/`, `italian/`). Each folder holds `get_daily_liturgy_<language>(date)`, a one-liner calling `get_ibreviary_liturgy(date, "<iBreviary code>")`. Map several locale keys to the same function instead of adding folders.
- `daily_liturgy/aelf/` holds the AELF API code shared by the French keys: `get_aelf_liturgy(date, zone, locale)`, registered once per key with `functools.partial`.
- `daily_liturgy/calendar/` holds locale-independent logic:
  - `get_season_and_week(date)` computes season and week from the General Roman Calendar rules (Easter computus; Epiphany on the Sunday from Jan 2 to 8, as in the US and Brazil). It's validated against a year of Canção Nova titles.
  - Week conventions: Advent 1–4. Christmas `None`. Lent: Ash Wednesday–Saturday 0, then 1–5, Holy Week 6. Triduum (Holy Thursday–Holy Saturday) `None`. Easter: Easter Sunday starts week 1, Pentecost is week 8. Ordinary Time 1–34 (after Pentecost counted back from Christ the King = 34).
- **Never guess color or celebrations** (the user's rule): they're taken only from what the source publishes. If the source doesn't provide them, return `color=None` and `celebrations=[]`. Don't derive them from the season, hardcoded feast lists or another site. (A `get_ferial_color` helper existed and was removed for this reason.) Season and week are computed for every locale, since they follow from the date alone.

Adding a locale: if iBreviary has the language, add a key mapped to the existing `daily_liturgy/ibreviary/<language>/` function (or add a one-line language folder). Otherwise create `daily_liturgy/locales/xx_yy/` with `get_daily_liturgy_xx_yy.py` plus its single-function fetch/parse files, register it in `SUPPORTED_LOCALES`, save a feed/page snapshot under `tests/fixtures/`, and add tests that monkeypatch the fetch function (see `tests/conftest.py`).

Note: `daily_liturgy/__init__.py` re-exports the function `get_daily_liturgy`. That function shadows the submodule of the same name as a package attribute, so import the module explicitly if you need to patch it.

## en-us: USCCB

- Source: the USCCB official RSS feed `https://bible.usccb.org/readings.rss`. `get_daily_liturgy_en_us` = `fetch_usccb_items` (download + RSS items) → `select_usccb_item` (the date's item) → `parse_usccb_readings` (description HTML → `Reading`s) + `parse_usccb_celebrations` (item title).
- Celebrations: from the item `<title>`. The prefixes "Solemnity/Feast/Memorial/Optional Memorial of" set the rank. Temporal titles ("Thursday of the … Week", "… Sunday in Ordinary Time", "Ash Wednesday", "December 19"…) mean no celebration. Any other title is an unranked celebration.
- Color: USCCB publishes none, so it's always `None`. The official yearly calendar PDF has colors but is copyrighted.
- The per-day pages (`bible.usccb.org/bible/readings/MMDDYY.cfm`) sit behind a proof-of-work bot challenge (HTTP 403). Do not scrape or bypass it. The RSS feed is the only data path.
- The feed covers about the last 10 days, with no future dates. Other dates raise `LiturgyNotAvailableError`, whose message gives the feed's date range.
- Items are matched by the `MMDDYY` code in `<link>`, not by `pubDate`. Multi-Mass days use suffixed links like `122526-Night.cfm`. `select_usccb_item` picks the unsuffixed link (assumed to be the Mass during the Day; not yet confirmed against a real multi-Mass feed), or the first match if there isn't one.
- `<description>` is HTML: `<h4>Kind <a>Citation</a></h4>` followed by `<div class="poetry"><p>…<br>…</p></div>`. An `<h4>or …</h4>` is an alternative to the previous reading. Citations may contain `&nbsp;` or stray spaces, so `_clean` in `parse_usccb_readings.py` normalizes them.
- `tests/fixtures/usccb_readings.rss` is a snapshot covering 2026-09-29 to 2026-10-08. The tests assert specific dates and citations from it. `tests/conftest.py` serves it (and the Spanish feed, see es-mx) by monkeypatching `_download_feed(feed_url)` in the `fetch_usccb_items` module.

## en-ph: CBCP

- Source: the Catholic Bishops' Conference of the Philippines, one WordPress post per day at `https://cbcp.ph/readings/<month>-<day>-<year>/` (lowercase, no zero padding: `october-8-2026`). Days are published in batches (in October 2026: 2026-06-08 to 2026-11-30, with a few June gaps; the full list is in `wp-sitemap-posts-daily_reading-1.xml`). A 404 raises `LiturgyNotAvailableError`.
- `get_daily_liturgy_en_ph` = `fetch_cbcp_page` → `parse_cbcp_readings`.
- Page structure: the day's title ("Memorial of Our Lady of the Rosary") is the `.et_pb_text_inner` module right after the one showing the date ("October 8, 2026"). It's deliberately not parsed (see below). Readings are `<h3>Type<br><span>Citation</span></h3>` followed by `<p>`s, in one text module. An alternative is a `<p>or</p>` followed by an `<h3>` with only spans (the citation may be split over two spans). The text is the US lectionary (NABRE) wording.
- Celebrations and color: always `[]` and `None` (the user's choice). CBCP's pages follow the general calendar rather than the Philippine one: 2026-09-28 is shown as "Monday of the Twenty-sixth Week", not the San Lorenzo Ruiz feast (red), and Santo Niño and San Pedro Calungsod may be missing too. So celebrations parsed from the title could be wrong, and CBCP publishes no color. Don't use Universalis for colors: its robots.txt disallows ClaudeBot, Claude-SearchBot, GPTBot and other AI agents site-wide.
- The readings themselves are fine on Sunday solemnities (2026-11-01 has All Saints' readings).
- Fixtures: `tests/fixtures/cbcp/<slug>.html` (2026-09-29, 10-04, 10-07, 10-08, 11-01). The `cbcp_site` fixture monkeypatches `fetch_cbcp_page` in the entry-point module.

## es-mx: USCCB en español

- Source: USCCB's official Spanish feed `https://bible.usccb.org/lecturas.rss` (the Mexican lectionary text, approved for the US). The `/es/...` pages, including `/es/bible/lecturas` and the per-day pages, are behind the same bot challenge (403), so don't use them. Same coverage as en-us: about the last 10 days.
- Reuses the en-us files: `fetch_usccb_items(USCCB_SPANISH_FEED_URL)` → `select_usccb_item` (matches both `/bible/readings/MMDDYY` and `/es/bible/lecturas/MMDDYY` links) → `parse_usccb_lecturas` + `parse_usccb_celebraciones`.
- Same HTML as the English feed, but the `<h4>` has no `<a>`: the citation is plain text ("Primera lectura Gálatas 3, 1-5", "Aclamación antes del Evangelio Cfr Hechos 16, 14", "Salmo Responsorial Del Salmo 26"). `split_usccb_heading` splits it with a list of known kinds, falling back to "the book name before the first verse number". `parse_usccb_lecturas` runs en-us's `parse_usccb_readings` and then splits each type. "O bien: <citation>" headings become alternatives.
- Celebrations: title prefixes "Memoria libre/opcional de", "Memoria de", "Fiesta de", "Solemnidad de" set the rank, and a leading article is dropped ("Fiesta de los santos Arcángeles…" → "Santos Arcángeles…"). Temporal titles ("Jueves de la XXVII semana del Tiempo ordinario", "XXVII Domingo ordinario", "Miércoles de Ceniza", "17 de diciembre"…) mean no celebration. Only the memorial/feast prefixes were seen in a real feed; the others are assumed. Color is always `None`, as in en-us.
- `tests/fixtures/usccb_lecturas.rss` is a snapshot covering 2026-09-29 to 2026-10-08.

## pt-br: Canção Nova (CNBB text)

- CNBB's own source is Edições CNBB (`liturgiadiaria.edicoescnbb.com.br`, API `api-liturgia.edicoescnbb.com.br`). It's what cnbb.org.br and the archdiocese sites embed, but the API returns 403 unless the request comes from a licensed customer domain. Don't spoof Origin/Referer. If the user gets API access, swap the source.
- Source used: `liturgia.cancaonova.com` (approved by the user). It publishes the CNBB translation ("Conferência Nacional dos Bispos do Brasil© Todos os direitos reservados") on the Brazilian calendar (e.g. Oct 12, Aparecida). It covers past dates and a few months ahead; unpublished dates raise `LiturgyNotAvailableError`.
- `get_daily_liturgy_pt_br` = `find_cancaonova_day_url` → `fetch_cancaonova_page` → `parse_cancaonova_readings` / `parse_cancaonova_color` / `parse_cancaonova_celebrations` (all on the same page HTML), with `split_cancaonova_pane` as a helper.
- Color: `<span class="cor-liturgica">Cor Litúrgica: Verde</span>`, mapping Verde/Roxo/Branco/Vermelho/Rosa/Preto. Unknown or missing gives `None`.
- Celebrations: from `h1.entry-title`, split on "|". The rank can be a separate part ("São Barnabé, Apóstolo | Memória"), a " - " suffix ("… - Festa") or a ", " suffix ("Santa Maria, Mãe de Deus, Solenidade"). Weekday parts are dropped. Temporal names ("27ª Semana…", "Depois das Cinzas", "Oitava da Páscoa", "Semana Santa", "Paixão do Senhor", "Tempo do Natal…") mean no celebration.
- `find_cancaonova_day_url`: day posts have unpredictable slugs. The URL comes from the month calendar widget: a POST to `wp-admin/admin-ajax.php` with `action=widget-ajax&sMes=M&sAno=YYYY&type=liturgia`, picking the link ending in `sDia=D&sMes=M&sAno=YYYY`. The `?sDia=` query params on the homepage are ignored server-side, and the WP REST API is disabled (302).
- Page structure: tabs `a#lit-N` (label = `type`, e.g. "1ª Leitura", "Salmo", "2ª Leitura", "Evangelho"; there's no separate Alleluia, because the acclamation is inside the Gospel text) map to panes `div#liturgia-N`. Each text starts with a bold header paragraph holding the citation ("Primeira Leitura (Gl 3,1-5)", "Responsório Sl …"). The header may list every option joined by "ou", so only the first is kept.
- In a pane, a `<p>ou</p>` paragraph separates alternatives. Multi-Mass days (Christmas) put "Missa da aurora" / "Missa do dia" lines in the same pane, and `split_cancaonova_pane` keeps "Missa do dia" to match en-us. The trailing CNBB copyright paragraph is dropped.
- Fixtures in `tests/fixtures/cancaonova/`: calendars `calendar_YYYY_MM.html` and day pages `YYYY_MM_DD.html` (2025-04-20, 2026-09-29, 10-04, 10-08, 12-25). The `cancaonova_site` fixture maps URLs to them by their `sDia/sMes/sAno` query.

## it-it: CEI (chiesacattolica.it)

- Source: the Italian bishops' conference "Messa del Giorno" pages, `https://www.chiesacattolica.it/liturgia-del-giorno/liturgie-del-YYYYMMDD/` (official). Coverage is about 2024 to end of 2026 as of Oct 2026; other dates are 404 → `LiturgyNotAvailableError`. Its robots.txt disallows only `ClaudeBot` (Anthropic's crawler); the path is allowed for other agents.
- `get_daily_liturgy_it_it` = `fetch_cei_page` → `split_cei_masses` → `parse_cei_readings` (with `split_cei_section`) / `parse_cei_color` / `parse_cei_celebrations`. Only `#cci_content_single` is used.
- Masses: a single Mass has its title `h3.cci_content_single_title` and sections directly in `#cci_content_single`. Multi-Mass days (Christmas, All Souls "MESSA 1/2/3", a weekday with an optional memorial) have toggle titles (`h3.cci-toggle-dropdown`) each followed by a `div.collapse`. The Christmas page repeats the set three times, so repeated titles are skipped. Readings and color come from "MESSA DEL GIORNO" if present, else the first Mass (the weekday's on optional memorials). Celebrations come from every Mass title.
- Color: `div.cci-colore-liturgico span` (verde/viola/bianco/rosso/rosa/rosaceo/nero), per Mass.
- Celebrations: titles are upper case and kept that way ("SANTI MICHELE, GABRIELE E RAFFAELE, ARCANGELI – FESTA"). Trailing " – FESTA/SOLENNITÀ/MEMORIA/MEMORIA FACOLTATIVA" (en dash or hyphen) sets the rank. " - ANNO A", " - MESSA DEL GIORNO" and "(MESSA …)"/"(ANNO …)" are dropped. Temporal titles (weekday names, "XXVII DOMENICA…", "DOMENICA DELLE PALME", "MERCOLEDÌ DELLE CENERI", "GIOVEDÌ SANTO…") mean no celebration. Easter Sunday is an unranked celebration.
- Sections: each `div.cci-liturgia-giorno-dettagli-content` with an `h2` title. Only titles matching lettura/salmo/acclamazione/vangelo/sequenza/epistola are readings (the rest are prayers and rites). `type` is the h2 text ("Prima Lettura", "Salmo Responsoriale", "Acclamazione al Vangelo", "Vangelo", "SEQUENZA").
- Citations: BibbiaEdu links (`a[href*="bibbiaedu.it"]`, usually inside `span.bibbiaedu-linked`, which can wrongly wrap the following text too). A citation can span several links ("Dn 7,9-10" "." "13-14"). The link line under "Dal libro…" is removed from `content`. Inline citations like "(Cf. At 16,14b)" stay in the text. An unlinked trailing "(Sal 102 (103),21)" is the fallback. The psalm's citation is `p.cci-liturgia-giorno-section-versetto` ("Dal Sal 137 (138)"). Some acclamations and the Sequence have none (`""`).
- Alternatives: a red rubric line (`span.cci-liturgia-giorno-testo-rosso`: "Oppure:", "Forma breve:", "Dove si celebra la Messa vespertina…") followed by its own citation starts an alternative. Red lines without a following citation, like the psalm's "Oppure:" between refrains, stay in the text.
- Fixtures in `tests/fixtures/cei/YYYY_MM_DD.html` are trimmed to `#cci_content_single` (2025-04-20; 2026-04-02, 09-29, 10-04, 10-06, 10-08, 12-25). The `cei_site` fixture patches `fetch_cei_page` in the `get_daily_liturgy_it_it` module.

## French: AELF (fr, fr-fr, fr-be, fr-lu, fr-ch, fr-mc, fr-ca)

- Source: the official AELF API (Association Épiscopale Liturgique pour les pays Francophones), `https://api.aelf.org/v1/messes/{YYYY-MM-DD}/{zone}`, JSON. robots.txt allows everything. Zones: `romain` (General Roman Calendar) → `fr`, `france` → fr-fr, `belgique` → fr-be, `luxembourg` → fr-lu, `suisse` → fr-ch, `monaco` → fr-mc, `canada` → fr-ca. The `afrique` zone isn't registered: it's not one country, so which keys it should serve is the user's call. Dates: about 2019 to the end of next year; others are 404 → `LiturgyNotAvailableError`.
- `get_aelf_liturgy` = `fetch_aelf_masses` → `parse_aelf_readings` (chosen Mass) + `parse_aelf_celebrations` (`informations`) + the color (`informations.couleur`: vert/violet/blanc/rouge/rose/noir).
- Masses: `messes` lists one entry per Mass ("Messe du jour"; on Christmas "Messe de la veille au soir", "de la nuit", "de l'aurore", "du jour"; at Easter "VEILLEE PASCALE", "MESSE DU JOUR DE PÂQUES"). The one whose `nom` contains "messe du jour" is used, else the first.
- Readings: `lectures` items have a `type` key (`lecture_1`…`lecture_7`, `psaume`, `cantique`, `epitre`, `sequence`, `evangile`), mapped to the site's headings ("Première lecture", "Psaume", "Cantique", "Épître", "Séquence", "Évangile"). An item with the same key as the one before is an alternative. The Gospel's `verset_evangile`/`ref_verset` becomes an "Acclamation" reading just before it. Content = `intro_lue` ("Lecture de la lettre…") or the psalm's `refrain_psalmique`, then `contenu` (HTML → text). `titre` (the summary line) isn't included. Citations (`ref`) are as published, and some psalm refs lack "Ps" ("97 (98), 1, …").
- Celebrations: feasts and solemnities have the name in `jour_liturgique_nom` and the rank in `degre` ("Fête", "Solennité", "Solennité du Seigneur"…); bracketed notes like "[Psautier semaine propre]" are dropped. Memorials have `jour_liturgique_nom` = "de la férie", the saint in `fete` and the rank in `ligne3` ("Mémoire", "Mémoire facultative"). Ferias and Sundays have neither. All Souls has no rank or `fete`, so it gets no celebration. National days are there (Canada's Marguerite Bourgeoys on Jan 12, Switzerland's Nicolas de Flüe solemnity on Sep 25).
- Fixtures: `tests/fixtures/aelf/YYYY-MM-DD_zone.json`. The `aelf_api` fixture patches `_download(url)` in `fetch_aelf_masses` and answers 404 for missing files.

## pl-pl: Konferencja Episkopatu Polski (episkopat.pl)

- Source: `https://episkopat.pl/liturgia/YYYY-MM-DD`, an official server-rendered page per day, available years back and ahead (2024 and 2027 checked). Every date returns 200, so a page without readings raises `LiturgyNotAvailableError`. robots.txt allows `/liturgia`.
- `get_daily_liturgy_pl_pl` = `fetch_episkopat_page` → `parse_episkopat_readings` + `parse_episkopat_celebrations`.
- Readings: each `.lit-right .subsec` has `<h2>` = type ("Pierwsze czytanie", "Psalm responsoryjny", "Drugie czytanie", "Werset przed Ewangelią (Alleluja)", "Ewangelia"), `.siglum` = citation, and the next `<div>` = text. Subsections without a `.siglum` (the "Homilie" links) are skipped. Line breaks are written as `</br>`, which `html.parser` would drop, so they're replaced by "\n" before parsing. An inline bracketed rubric "[lub do wyboru: Ap 12, 7-12a]" or "[Lub: (podczas Mszy wieczornej w niedzielę): Łk 24, 13-35]" starts an alternative, with the citation after the last ":". Other bracketed notes stay in the text, e.g. "[Zamiast poniższej Ewangelii można odczytać Ewangelię z Wigilii Paschalnej.]". The psalm text often starts with the full psalm citation, while `.siglum` has the short one ("Ps 118"); both are kept as published. Christmas shows the Mass during the Day, with the other Masses' citations listed in a note at the end of the Gospel.
- Celebrations, from `.period_name`, only when the title names a rank:
  - "Uroczystość …" → solemnity
  - "Święto …" → feast
  - "Wspomnienie (obowiązkowe) …" → memorial
  - "Wspomnienie dowolne …" → optional memorial
  - "Dzień powszedni albo wspomnienie X albo wspomnienie Y" → one optional memorial each
  
  The name is the rest of the title, in the genitive as published. Titles without a rank give `[]` (the no-guessing rule). That covers temporal ones ("XXVII Tydzień zwykły", "Wielki Post - Środa Popielcowa", "Dzień Powszedni", "Triduum Paschalne") and also "Zesłanie Ducha Świętego", "Chrystusa Króla", "Niedziela Palmowa" and "Niedziela Świętej Rodziny". All Souls ("Wspomnienie wszystkich wiernych zmarłych") gets `rank=None`, since it's a commemoration, not a memorial.
- Color: none on the page (the `.kielich` chalice has no color class or style), so always `None`. The site also embeds an `opoka.org.pl/liturgia_iframe` widget, which isn't used.
- Fixtures: `tests/fixtures/episkopat/YYYY-MM-DD.html` (2025-04-20, 2026-09-29, 10-04, 10-07, 10-08, 10-12, 11-01, 12-25). The `episkopat_site` fixture monkeypatches `fetch_episkopat_page` in the entry-point module.

## de-de: Schott (Erzabtei Beuron)

- Source: `schott.erzabtei-beuron.de` (approved by the user), the Archabbey of Beuron's online Schott with the German Messbuch/Lektionar texts on the calendar of the German-speaking dioceses. robots.txt has only a content-signals preamble with no rules or signals. The server is slow and sometimes stops answering for a while, so timeouts are 45 s.
- `get_daily_liturgy_de_de` = `fetch_schott_index` (calendar) + `find_schott_path` (resolved page) → `fetch_schott_page` → `select_schott_mass` (index pages) → `parse_schott_readings` (with `select_schott_headings`) + `parse_schott_celebrations`. No color.
- Calendar index: `https://liturgie-server.de/dyn/schott.json?date=YYYY-MM-DD`, the data behind the site's date widget. It's a JavaScript object literal (bare keys, single quotes, `\xNN` escapes, `null`) wrapped in `window.Schott.loadedData( … );`, parsed by quoting keys and `ast.literal_eval`. It covers about a week each side of the date. Per day: `LESEJAHR_S` (1-3 = Sunday cycle A-C), `LESEJAHR_W` (1-2 = weekday Year I/II), `NON_PROPRIUM` (temporal day: `NAME_DE`, page `url`), `PROPRIUM` (saints: `NAME_DE`, `DESCRIPTION`, `TYPE_D` H/F/G/g = Hochfest/Fest/Gedenktag/nicht gebotener Gedenktag, page `url`; several entries can share a page).
- Resolved page: `/?datum=YYYY-MM-DD` answers 302 to the page Schott chose after its precedence rules (Sunday over St. Francis on 2026-10-04), e.g. `/jk27/Donnerstag.htm?datum=…`. No redirect (e.g. 2010) → `LiturgyNotAvailableError`. On memorials (`TYPE_D` G/g) it's the saint's page, with readings chosen for the saint, so the first `NON_PROPRIUM` page (the weekday) is used for readings instead, as in the other locales. `source_url` is the page the readings came from.
- Index pages: Christmas (`weihnachten_register.htm`) and Easter Sunday (`Nachtrubrik.htm`) are lists of `…/schott_anz/index.html?file=<path>` buttons: "Am Heiligen Abend" … "Am Tag", or `dt` "Osternacht"/"Sonntag" with A/B/C buttons. The "Am Tag"/"Sonntag" link of the Sunday cycle is followed.
- Page structure (`#schott`): readings are `h2.lb_u1` with the citation in `span.lb_right` ("Vers: " stripped from acclamations) and a `span.marg` number on numbered options. On weekday pages the acclamation is an `h2.s_u1` "RUF VOR DEM EVANGELIUM". Prayers are `h2.s_u1`, and non-reading `lb_u1` like "Präfation …" are dropped. Text is the following `p.lb_tx` until the next heading; `p.s_rub` (introductions "ZUR LESUNG", rubrics), verse numbers (`span.vers`), hymnal numbers (`span.lb_right` "GL 616") and "Oder:" lines are dropped. Types are normalized for case ("ERSTE Lesung" → "Erste Lesung").
- `h4.lb_u_datum` markers: "Jahr I"/"Jahr II"/"Jahr I und II" weekday cycles; some pages omit "Jahr II" (jk27/Dienstag), so a new "Erste Lesung" after a psalm in "Jahr I" starts Year II. Other markers split Masses on one page ("Am Vorabend"/"Am Tag" on Aug 15, "I"/"II"/"III" on All Souls): "Am Tag" is kept, else the first. A date marker ("15. August") is ignored.
- Alternatives: a reading with the same type as the one before (after an "Oder:" or "Oder Kurzfassung:" line).
- Celebrations: the resolved page's `PROPRIUM` entries give the rank. The name is the saint page's first non-date `h1.lb_u_tag` up to its `<br>` ("Mariä Aufnahme in den Himmel"; the index just says "Maria") when that page was fetched, else the entries' names joined (memorials). A temporal page is a celebration only when its `NAME_DE` contains "Hochfest"/"Fest" ("Weihnachten - Hochfest der Geburt des Herrn"); Easter Sunday ("Ostersonntag") has none. All Souls is `TYPE_D` H, so a solemnity.
- Only `de-de` is registered. Austria and Switzerland have their own proper days, which haven't been checked against this calendar.
- Fixtures in `tests/fixtures/schott/`: `index/YYYY-MM-DD.js`, `redirects.json`, and trimmed `pages/<path with / as __>` (2025-04-20; 2026-08-15, 09-29, 10-06, 10-08, 12-25). The `schott_site` fixture patches `_download`, `_redirect_location` and `fetch_schott_page`.

## iBreviary (la, en, es-es, pt-pt, ro-ro, gl-es, ar)

- Why: no official source publishes the daily readings in Latin (the Holy See doesn't; Evangelizo has no Latin). For Spain, the CEE's liturgy site (`liturgia.conferenciaepiscopal.es`) was under maintenance, and the Málaga diocese page only has today's readings, with no date. The user chose iBreviary (`ibreviary.com/m2`) for these languages.
- Languages and texts, checked against national days: `es` = Spain's CEE lectionary and calendar (Pilar on Oct 12 has its own readings). `pt` = Portugal's (Fátima on May 13; "Actos", "Leccionário"). `en` = the US lectionary text (identical to USCCB's wording) on the general Roman calendar (no US feasts), so it's registered only as generic `en`, not en-gb/en-ie/en-au, whose countries read other translations. `fr` (AELF text) was registered as fr-fr until AELF's own API replaced it. Skipped: `mo` (monastic rite) and `vt` (Vetus Ordo: other calendars; vt pages are empty).
- Flow: `get_ibreviary_liturgy(date, language)` = `fetch_ibreviary_page` → `parse_ibreviary_readings`, with the helpers `split_ibreviary_blocks`, `split_ibreviary_alternatives` and `find_ibreviary_citation`. If no reading has both a citation and text, it raises `LiturgyNotAvailableError`. Some pages keep their headings with empty text (ro/gl Easter 2025).
- Date selection is session-based: POST `opzioni.php` (`lang=<code>&giorno=D&mese=M&anno=YYYY&ok=ok`), then GET `letture.php?s=letture` with the same cookies. The options response echoes the date in its language ("Dies: Feria tertia, 29 September 2026", "يوم: يوم الخميس, 8 تشرين الأول - أكتوبر 2026"), checked as "day … year" with no digits between. There's no per-date URL, so `source_url` is always the readings page. The site is slow (10–20 s per request), sometimes times out, and accepts any date.
- Celebrations and color: the pages name neither, so `celebrations` is always `[]` and `color` always `None`.
- Sections (`split_ibreviary_blocks`): `span.sezione` labels are translated ("Letture proprie", "Proper readings", "Leituras Próprias", es's second "Lecturas"…), so they're handled by position. The first section containing a `span.titolo` wins: the proper readings on saints' days (required on feasts, allowed on memorials), or else the page's only section. The trailing "Preghiera dei fedeli" section (it, gl) is never chosen. Top-level `<p>` and `<div>` (es) are content, split into blocks by `<hr>`.
- Readings (`parse_ibreviary_readings`): a block starting with `span.titolo` is a reading. A block without one (Latin) is an alternative to the previous reading.
- Citations: the first run of `span.citazione` in a text. Back-to-back citations, i.e. a heading listing every option followed by the text's own, keep the last. A `citazione` with no digits isn't a reference (en marks an antiphon that way) and stays in the text. Italian has an empty `citazione` and puts the reference in a rubric, so `find_ibreviary_citation` regex-searches the text start. A heading listing options ("Col 3:1-4 or I Cor 5:6b-8") gives the main its first option and supplies missing alternative citations.
- Inline alternatives (`split_ibreviary_alternatives`): a `.rubrica` matching the language's marker starts an alternative: en "Or:" / "Or, at an afternoon…:" (not the psalm's "or:℟."), it "Oppure", es "(opción 2)" / "O bien", pt "Ou …" / "Em vez da leitura precedente" / "Nas Missas Vespertinas", gl "Ou:". Psalms are never split, because their "or" offers another refrain. Alternatives without any citation are dropped (e.g. the en Easter renewal of baptismal promises), and a first line that repeats the citation or the "or" word is removed.
- Source data quirks, returned as published: Christmas shows a different Mass per language (en/es Night, it Dawn, la Vigil, gl Day). All languages show the 31st Sunday on 2026-11-01 instead of All Saints. Arabic citations of some texts come out with reversed digit order. Latin has OCR-like typos ("Ps l38"). Galician `type`s are iBreviary's Italian labels.
- Fixtures: `tests/fixtures/ibreviary/<code>/YYYY_MM_DD.html`. The `ibreviary_site` fixture monkeypatches `_download(date, language)` and fakes the options page.
